## 1. 한 줄 요약

사용자가 블록 코딩으로 짠 순서대로 캐릭터 '나우'가 8×8 마트를 돌며 물건을 집고, **집은 순서 그대로 케이크가 바닥부터 쌓이는** 브라우저 게임. ASV(안산 사이언스 밸리) 부스용, 초·중등 및 코딩 입문자 대상.

## 2. 기술 스택

| 항목 | 선택 | 비고 |
|---|---|---|
| 플랫폼 | 웹 브라우저 (HTML5/CSS3/JS) | 모바일·태블릿 포함, QR로 바로 접속 |
| 블록 코딩 | Google Blockly | 데모는 v13.3.0, zelos 렌더러(스크래치풍, 터치 친화) |
| 애니메이션 | CSS 애니메이션 (기획안의 GSAP는 선택) | 데모는 GSAP 없이 구현됨 |

| 저장 | localStorage (명예의 전당) | 기기·브라우저 단위. 부스 공용 랭킹은 서버 필요 |
| 배포 | GitHub Pages (단일 `index.html`) | 데모는 Blockly를 파일에 인라인해 외부 의존 0 |

## 5. 맵 (기획서 7번, 8×8)

```
r\c  0      1     2     3      4   5        6    7
0    입구   .     .     .      .   딸기     벽   초
1    .      벽    벽    빵     벽  생크림   벽   다이너마이트
2    .      벽    .     .      벽  .        .    .
3    .      벽    .     .      벽  .        .    .
4    .      .     .     .      .   .        .    .
5    .      .     생크림 .     벽  .        .    .
6    .      .     벽    양말   .   다이아    벽   벽
7    벽돌   빵    벽    초콜릿 .   .        .    계산대
```

코드 표현 (`#`=선반/벽, `.`=통로, `S`=입구, `E`=계산대):

```js
const MAP = [
  ['S','.','.','.','.','딸기','#','초'],
  ['.','#','#','빵','#','생크림','#','다이너마이트'],
  ['.','#','.','.','#','.','.','.'],
  ['.','#','.','.','#','.','.','.'],
  ['.','.','.','.','.','.','.','.'],
  ['.','.','생크림','.','#','.','.','.'],
  ['.','.','#','양말','.','다이아몬드','#','#'],
  ['벽돌','빵','#','초콜릿','.','.','.','E'],
];
```

아이템 분류

| 종류 | 아이템 | kind |
|---|---|---|
| 정상 | 빵 🍞, 생크림 🍦, 딸기 🍓, 초콜릿 🍫, 초 🕯️ | bread / cream / topping / topping / deco |
| 함정 | 양말 🧦, 벽돌 🧱, 다이아몬드 💎 | trap |
| 폭발 | 다이너마이트 🧨 | boom |

- 레시피: **빵 → 생크림 → 빵 → 생크림 → 토핑(딸기 또는 초콜릿) → 장식(초)**, 총 6개.
- 아이템은 집어도 사라지지 않음 (같은 선반에서 다시 집기 가능).
- 와사비는 기획서 아이템 목록에는 있으나 맵에 없음 → 미배치.

## 6. 블록 사양

| 블록 | 동작 | 비고 |
|---|---|---|
| 앞으로 가기 | 보는 방향으로 1칸. 앞이 벽/맵 밖이면 제자리 + "쿵" | bump 카운트 |
| 왼쪽/오른쪽으로 돌기 | 제자리 90° 회전 | |
| 앞에 있는 물건 집기 | 앞 칸에 아이템이 있으면 케이크 배열에 push. 없으면 아무 일 없음 | 다이너마이트면 즉시 폭발 종료 |
| N번 반복하기 | 내부 블록 N회 실행 (1~20) | 중첩 가능 |
| 만약 ~라면 | 조건 4종 (아래) | 내부 블록 1회 |

조건 4종 (기획서 그대로)

| 조건 | 데모 해석 |
|---|---|
| 앞에 벽이 있다면 | 앞 칸이 `#` 또는 맵 밖 |
| 앞에 벽이 없다면 | 위의 부정 |
| 빵을 집었다면 | **마지막으로 집은 물건**이 빵 |
| 생크림을 집었다면 | 마지막으로 집은 물건이 생크림 |

"집었다면" 두 조건은 빵(1,3)과 생크림(1,5) 사이를 왕복할 때 회전 방향을 분기하는 용도로 쓰이며, 이걸 쓰면 반복 1개로 빵·크림 4개를 모을 수 있음(아래 8절 참고).

## 7. 실행 규칙 (데모에서 확정한 것)

- 시작 위치 (0,0), 동쪽을 봄.
- **아이템 칸은 지나갈 수 있음.** 집기는 "앞 칸"만 대상. → 이유: 기획서 맵에서 초(0,7)의 이웃은 벽(0,6)과 다이너마이트(1,7)뿐이라, 아이템 칸을 못 지나가면 초를 영원히 못 집음. 다이너마이트 칸 위에 서서 북쪽을 보고 집으면 초, (2,7)에서 북쪽을 보고 집으면 다이너마이트 → 의도된 함정으로 해석.
- 계산대(7,7)에 들어가면 실행 종료. 점수 가감 없음(기획서에 없음).
- 다이너마이트를 집으면 즉시 종료 + 폭발 엔딩.
- 안전장치: 실행 단위 600회 초과 시 강제 종료 (반복 중첩 폭주 방지).
- 워크스페이스에 연결 안 된 블록 뭉치가 여러 개면 위→아래 순서로 전부 실행 (경고 토스트).

## 8. 점수 및 순위 (기획서 8번)

가점·감점

| 항목 | 규칙 | 점수 |
|---|---|---|
| 정상 재료 | 레시피 순서와 맞는 층 (개당) | +50 (6개 = 300 만점) |
| 순서 오류 | 정상 재료지만 순서가 다른 경우 (개당) | −10 |
| 이상한 재료 | 양말·벽돌·다이아몬드 (개당) | −20 |
| 다이너마이트 | 폭발 엔딩 | −100 |
| 빈손 | 아무것도 안 집음 | 0 |

판정 알고리즘 (데모)

```
good = 케이크 배열에서 함정·폭발 제외
for i, item in good: RECIPE[i]와 kind가 같으면 +50, 아니면 −10
함정 개당 −20, 다이너마이트 −100
perfect = good이 정확히 6개이고 전부 일치 && 함정 0개
```

엔딩 4종: 완벽(효도 성공) / 이상한 케이크(칼 부러짐) / 빈손(등짝 스매싱) / 폭발.

순위 (명예의 전당): ① 점수 ↓ → ② 블록 수 ↑ → ③ 실행 동작 수 ↑ (기획서의 "시간" 대신 동작 수로 대체, 속도 설정과 무관하게 공정).

칭호 (완벽한 케이크일 때만): 블록 ≤45 "알고리즘 장인", ≤65 "효도 코더", 그 외 "효도 성공".
기준 근거: 조건문 활용 최적 풀이가 39블록(동작 57), 반복문만 쓰면 ~57블록, 전부 나열하면 80블록 이상.

참고용 최적 풀이 (39블록, 300점)
```
오른쪽 / 4번{앞} / 왼쪽 / 3번{앞} / 왼쪽 / 2번{앞} / 집기          ← (2,3)에서 빵
3번 반복 {
  오른쪽 오른쪽 / 2번{앞}
  만약 빵을 집었다면 {왼쪽}  만약 생크림을 집었다면 {오른쪽} / 2번{앞}
  만약 빵을 집었다면 {왼쪽}  만약 생크림을 집었다면 {오른쪽} / 2번{앞}
  집기                                                           ← 생크림, 빵, 생크림
}
앞 / 집기                                                         ← (1,5)에서 딸기
오른쪽 오른쪽 / 앞 / 왼쪽 / 2번{앞} / 왼쪽 / 앞 / 집기              ← (1,7) 다이너마이트 위에서 초
```

## 13. 미결 사항 (결정 필요)

1. **아이템 칸 통과 허용 여부** — 데모는 허용. 불허하면 초(0,7)가 닿지 않으므로 맵 수정 필요 (예: (0,6) 벽 제거).
2. **"빵을 집었다면" 의미** — 데모는 "마지막으로 집은 것". "앞에 빵이 있다면"으로 바꾸면 탐색형 코드는 쉬워지지만 8절의 왕복 트릭은 사라짐.
3. **계산대 도착 의무화 / 보너스** — 현재 점수 무관이라 아이들이 안 감.
4. **음수 점수 허용** — 다이너마이트 −100으로 음수 가능. 0으로 바닥을 둘지.
5. **"시간" 순위 기준** — 데모는 동작 수. 실제 초 단위를 쓰려면 속도 옵션을 없애야 공정.
6. **쿼터뷰 vs 평면** — 데모는 평면. 입체 에셋 확보 여부에 달림.
7. **인증서/상장 발급** — 통과 시 PDF 생성? 부스 인쇄?
8. **토핑 2종 중복** — 딸기+초콜릿 둘 다 집으면 현재는 두 번째가 순서 오류(−10). 둘 다 허용할지.
9. **어린 연령 모드** — 반복·조건 없이 나열만 해도 통과로 치는 쉬운 모드 필요 여부.
