# 장보기 게임 개편 작업 명세

- 대상 브랜치: `tomatolovers`
- 대상 프로젝트: `ASV-project`
- 문서 목적: 아래 요구사항을 구현 작업과 완료 검토에 바로 사용할 수 있는 기준으로 정리한다.
- 범위: 기존 웹 게임의 플레이 흐름, 레벨, 장바구니, 블록, 점수 안내, 화면 배치 개편
- UI 방향: 기존 색상, 글꼴, 카드·버튼·블록의 시각 스타일은 유지한다.

## 1. 개편 목표

케이크 만들기 중심의 게임을 **마트에서 필요한 물건을 장바구니에 담는 블록 코딩 게임**으로 바꾼다. 아이는 학년에 맞는 레벨을 고르고, 나우가 블록 명령대로 이동해 장보기 목록의 물건을 담도록 코드를 만든다. 코드를 끝내려면 마지막에 `계산하기` 블록을 실행해야 결과 화면으로 이동한다.

## 2. 플레이 흐름

1. 시작 화면에서 아이가 레벨 1 또는 레벨 2를 선택한다.
2. 게임 화면에 선택한 레벨의 마트 지도, 장보기 목록, 장바구니, 블록 코딩 도구와 실행 컨트롤을 표시한다.
3. 아이가 이동·회전·담기 블록을 연결해 장보기 경로를 만든다.
4. 실행하면 나우가 코드를 따라 움직이고, 담은 물건이 장바구니에 표시된다.
5. 아이가 프로그램의 **마지막 블록**으로 `계산하기`를 놓고 실행하면 장보기를 마감하고 결과 화면으로 이동한다.

계산대 타일과 계산대 도착 방식은 없앤다. 결과 화면은 지도상의 특정 칸에 도착했는지가 아니라 `계산하기` 블록 실행으로 연다.

## 3. 레벨과 장보기 데이터

| 레벨 | 대상 | 지도 크기 | 장보기 목록 | 함정 아이템 |
|---|---|---:|---|---|
| 레벨 1 | 초등 1~3학년 | 5×5 | 토마토, 감자, 고구마 | TNT |
| 레벨 2 | 초등 4~6학년 | 7×7 | 계란, 베이컨, 빵, 케첩, 우유 | 초콜릿, 양말, 다이아몬드 |

- 레벨 선택 화면에는 두 레벨을 모두 보여주고, 학년 범위와 지도 크기를 함께 안내한다.
- 레벨별 장보기 목록은 게임 화면과 장바구니 근처에서 계속 확인할 수 있게 한다.
- 지도는 지정한 행·열 크기를 정확히 사용한다. 시작 위치, 통로, 벽, 장보기 품목과 함정의 배치는 각 레벨의 크기에 맞게 구성한다.
- 각 장보기 품목은 경로를 짜서 실제로 담을 수 있어야 한다. 벽이나 진열대가 품목과의 접근 경로를 막지 않도록 맵을 설계한다.
- 벽과 지도 바깥은 이동할 수 없다. 아이템이 놓인 칸은 통로처럼 이동할 수 있으며, 그 칸에 올라선 뒤 현재 위치의 아이템을 담는다.
- 아직 담지 않은 아이템이 있는 칸도 이동 가능하다. 아이템을 담은 칸은 아이템 표시를 제거하고 계속 이동 가능한 통로로 취급한다.
- 레벨 1의 TNT는 폭발 함정으로 취급한다. 레벨 2의 초콜릿·양말·다이아몬드는 장보기 목록에 없는 함정 물건으로 취급한다.
- 두 레벨만 제공한다. 기존 3레벨 선택, 8×8 지도, 케이크 재료·레시피, 케이크 쌓기 표현은 새 장보기 흐름에서 제거한다.

## 4. 블록 코딩과 완료 조건

### 유지할 조작

- 앞으로 이동
- 왼쪽으로 돌기
- 오른쪽으로 돌기
- `여기 물건 담기` (나우가 현재 서 있는 칸의 물건을 장바구니에 담기)
- N번 반복하기
- 조건 블록

현재 이동·반복·조건 블록의 동작과 Blockly 기반 조립 방식은 유지한다. 블록 문구, 툴팁, 시작 블록 구성은 장보기 용어와 각 레벨의 난이도에 맞춘다.

### 물건 담기 블록

- 블록 이름은 **`여기 물건 담기`**로 한다. 아이가 동작 위치를 바로 이해할 수 있도록 `여기`를 사용한다.
- 툴팁/간단 설명은 `나우가 서 있는 칸의 물건을 장바구니에 담아요.`로 표시한다.
- 실행 시 나우의 현재 좌표에 아이템이 있으면 그 아이템을 장바구니에 추가한다. 앞 칸의 아이템은 담지 않는다.
- 현재 칸에 아이템이 없으면 장바구니와 점수를 변경하지 않는다. 필요하면 기존 말풍선/간단 안내로 `여기에는 담을 물건이 없어요.`를 표시한다.
- 아이템 칸은 걸어 들어갈 수 있다. 따라서 이동 명령으로 아이템 칸에 도착한 뒤 `여기 물건 담기`를 실행하는 순서가 된다.
- 담은 아이템은 해당 칸에서 제거한다. 다시 그 칸에 와서 실행해도 동일 아이템을 중복 획득하지 않는다.
- 조건 블록의 `앞에 벽이 있다면/없다면` 판정은 이동 가능 여부와 일치시킨다. 아이템 칸은 이동 가능하므로 벽으로 판정하지 않고, 벽·지도 바깥만 막힌 칸으로 판정한다.

### 시작 가이드 블록

- Blockly 워크스페이스를 처음 열 때 레벨별 **약 3개의 연결된 가이드 블록**을 미리 배치한 상태로 시작한다.
- 가이드 프로그램은 시작 위치에서 가장 가까운 장보기 품목까지 이동하고, 그 품목 칸에서 `여기 물건 담기`를 실행하는 짧은 예시로 구성한다.
- 가이드에는 새 `여기 물건 담기` 블록을 반드시 포함해, 이동한 뒤 현재 칸의 물건을 담는 방식이 코드로 드러나게 한다.
- 가이드는 선택한 레벨의 실제 지도와 시작 방향에 맞게 만든다. 시작 블록이 아이템에 도달하지 못하거나 함정 칸으로 가면 안 된다.
- 가이드는 첫 품목의 짧은 예시만 제공한다. 전체 장보기 풀이와 마지막 `계산하기`는 아이가 이어서 완성하도록 둔다.
- `블록 지우기`는 작업 공간을 비운다. `가이드 다시 놓기`를 누르면 현재 레벨의 가이드 3개와 초기 지도를 복원한다. 기존 블록이 있으면 교체 전에 확인한다. 레벨을 바꿔 시작할 때도 해당 레벨의 가이드를 제공한다.

### 새 블록: `계산하기`

- 블록 이름은 `계산하기`로 표시한다.
- 장바구니와 획득 항목을 마감하고 결과를 계산한 뒤 결과 화면으로 이동시킨다.
- 아이가 작성한 코드는 한 줄로 연결한다. `계산하기`는 반복·조건 블록 밖의 맨 마지막에 한 개만 놓는다. 떨어진 블록이나 잘못 놓은 계산하기가 있으면 실행 전에 위치를 고치도록 안내한다.
- `계산하기` 없이 코드가 끝나면 결과 화면으로 자동 이동하지 않는다. 게임 화면에 `장보기를 마치려면 마지막에 계산하기 블록을 넣어 주세요.`라는 안내를 표시한다.
- `계산하기` 뒤에 추가 실행 블록이 연결된 코드는 완료 처리하지 않는다. 마지막 블록 위치를 고치도록 같은 안내를 표시한다.
- 계산하기가 실행되면 이후 블록은 실행하지 않는다.

### 실행 종료

- TNT를 담으면 기존 폭발 연출을 유지하고 해당 실행을 즉시 종료한다. 결과 화면에서는 TNT 감점을 반영한다.
- 벽 또는 지도 바깥을 향한 이동은 이동하지 않고 충돌 횟수만 기록한다.
- 장보기 목록을 다 채웠더라도 결과 화면은 `계산하기`가 실행되어야 열린다.
- 중단 버튼은 실행만 멈추며, 계산하기가 실행되지 않았다면 결과 화면으로 보내지 않는다.

## 5. 장바구니와 점수

- 케이크 미리보기·층 쌓기 UI를 장바구니 UI로 교체한다.
- 장바구니에는 실제로 담은 순서대로 이모지 또는 현재 프로젝트의 아이템 표현을 추가한다.
- 게임 화면의 장보기 목록은 담은 품목을 시각적으로 구분한다. 예: 미담음/담음 상태 표시.
- 레벨 1 목록은 토마토·감자·고구마 3종, 레벨 2 목록은 계란·베이컨·빵·케첩·우유 5종으로 고정한다.
- 품목을 한 번 담으면 해당 품목은 완료 표시한다. 중복으로 담은 품목은 장바구니에는 기록하되, 필수 품목 수를 추가로 채운 것으로 보지 않는다.
- 결과 화면은 선택 레벨, 점수, 장바구니 내용, 빠뜨린 품목, 블록 수와 실행 동작 수를 보여준다. 기존 케이크 층별 판정 표시는 장보기 결과에 맞게 바꾼다.

### 점수 안내와 판정 기준

블록 코딩 영역 위에 짧은 점수 안내를 항상 표시한다. 긴 규칙 설명이나 접기식 규칙 패널은 두지 않는다.

화면 안내 문구:

> 장보기 품목 +50점 · 목록에 없는 물건 −20점 · TNT −100점

판정 기준:

- 장보기 목록에 있는 **서로 다른 품목**을 처음 담을 때마다 +50점.
- 이미 담은 장보기 품목을 다시 담으면 추가 점수는 없다.
- 장보기 목록에 없는 일반 물건을 담으면 −20점.
- TNT를 담으면 −100점 및 즉시 폭발 종료.
- 계산하기 시점에 목록 품목을 모두 담았는지 판정한다. 빠뜨린 품목은 추가 점수를 주지 않으며, 결과 화면에서 미완료 품목으로 표시한다.
- 최종 점수의 하한은 0점으로 한다.

## 6. 화면과 레이아웃

### 스타일 유지

- 기존의 색상 팔레트, 타이포그래피, 테두리·그림자, 버튼 모양, Blockly 테마와 캐릭터 연출을 유지한다.
- 콘텐츠의 이름, 데이터, 정보 배치와 화면 흐름만 장보기 게임에 맞게 바꾼다. 전면적인 시각 재디자인은 범위에 포함하지 않는다.

### 상단 바 제거

- 페이지 최상단에 있는 흰색 상단 바를 화면에서 제거한다.
- 제거된 영역만큼 시작 화면과 게임 화면의 수직 공간을 다시 배분한다. 빈 띠나 대체 헤더를 새로 만들지 않는다.

### 한 화면에 맞추기

- 데스크톱의 게임 진행 화면에서 지도, 장보기 목록, 장바구니, 블록 코딩, 실행·초기화·레벨 변경 컨트롤이 한 화면에 들어오게 한다.
- 규칙/설명 패널은 제거한다. 그러므로 규칙 패널을 제외한 핵심 플레이 UI가 한 화면 기준이다.
- 안내 말풍선의 `블록을 조립하고 실행을 눌러요!` 문구는 제거하고, 같은 자리에 현재 레벨의 장보기 목록을 표시한다.
- 목록은 빠짐없이 읽을 수 있게 하고 장바구니와 혼동되지 않도록 담은 상태를 표시한다.
- 게임 화면에서 세로 페이지 스크롤바가 생기지 않게 높이와 내부 영역을 조정한다. Blockly 내부 스크롤/줌 등 편집기 조작은 허용한다.
- 창 높이가 낮은 경우 지도와 Blockly 영역을 우선 축소해 핵심 컨트롤이 화면 밖으로 밀리지 않게 한다. 작은 화면은 기존 반응형 구조를 유지하면서 가능한 뷰포트에 맞게 재배치한다.
- 결과 화면은 별도 화면으로 유지하며, 이 요구의 한 화면 배치 기준은 플레이 화면에 적용한다.

## 7. 기존 기능 정리

다음 케이크 중심 요소와 계산대 완료 방식을 새 흐름에서 제거하거나 장보기 표현으로 대체한다.

- 케이크 스토리, 레시피, 케이크 층 쌓기 애니메이션 및 케이크 결과 판정
- 계산대 타일, 계산대 범례, 계산대에 도착하면 종료되는 엔진 규칙
- 초콜릿/양말/벽돌/딸기/생크림 등 기존 레벨 맵 전용 재료와 기존 3레벨 맵
- `블록 설명과 규칙` 접기 패널 및 긴 규칙 목록
- 장보기 목록 대신 표시되던 실행 유도 말풍선 문구
- 레벨 3 URL 고정·선택 등 3레벨에만 해당하는 노출 경로

기존 UI의 스타일, Blockly 편집 상호작용, 이동·회전·반복·조건 실행, 점수 결과 화면의 기본 시각 언어는 유지한다. 명예의 전당 등 결과 후 기능은 장보기 점수·아이템 데이터와 일관되게 동작하도록 필요한 데이터 이름과 표시를 갱신한다.

- [x] `여기 물건 담기`는 나우의 현재 칸만 검사하며 앞 칸의 아이템을 담지 않는다.
- [x] 아이템을 담으면 해당 칸에서 아이템이 제거되어 재획득할 수 없다.
- [x] 조건 블록의 벽 감지는 벽·지도 바깥만 막힌 칸으로 취급하고 아이템 칸은 이동 가능한 것으로 취급한다.
- [x] 각 레벨을 처음 시작하면 가까운 필수 품목까지 이동한 뒤 담는 약 3개의 연결된 가이드 블록이 배치되어 있다.
- [x] 가이드 블록에 새 `여기 물건 담기` 블록이 포함되고, 전체 정답이나 `계산하기`는 미리 완성되어 있지 않다.
- [x] 레벨 1에는 TNT 함정, 레벨 2에는 초콜릿·양말·다이아몬드 함정이 배치되어 있다.
- [x] 장바구니가 담은 순서를 표시하고 장보기 목록의 품목별 담음 상태가 갱신된다.
- [x] `계산하기`가 마지막 실행 블록으로 실행될 때 점수를 확정하고 결과 화면으로 이동한다.
- [x] 계산하기가 없거나 마지막이 아니면 결과 화면으로 넘어가지 않고 고칠 위치를 안내한다.
- [x] 점수 안내가 Blockly 위에 짧게 표시되며, 기존 긴 규칙/블록 설명 패널은 없다.
- [x] 플레이 화면 말풍선 자리에 장보기 목록이 보이고 이전 실행 유도 문구는 없다.
- [x] 최상단 흰색 바가 제거되어 있다.
- [ ] 기존 시각 스타일은 유지되고 플레이 화면의 핵심 UI가 페이지 세로 스크롤 없이 보인다. 구현 및 여러 화면 크기 검증은 진행했으나, 1024×600에서 발견한 장바구니·점수 간격의 마지막 CSS 보정 후 재확인은 남아 있다. 추가 테스트는 사용자 요청에 따라 중단했다.
- [x] 결과 화면의 품목·점수·누락 정보가 장보기 기준이며 케이크 전용 표시는 남아 있지 않다.

## 9. 구현 확인 시나리오

1. 레벨 1을 선택해 지도가 5×5이고 토마토·감자·고구마 목록이 보이는지 확인한다.
2. 레벨 2를 선택해 지도가 7×7이고 계란·베이컨·빵·케첩·우유 목록이 보이는지 확인한다.
3. 새 레벨을 시작했을 때 약 3개의 가이드 블록이 가장 가까운 품목 칸으로 이동한 뒤 `여기 물건 담기`를 실행하는지 확인한다.
4. 아이템 칸에 이동해 `여기 물건 담기`를 실행했을 때만 현재 칸의 품목이 장바구니에 들어가고, 앞 칸 품목은 담기지 않는지 확인한다.
5. 담긴 아이템이 지도에서 사라지고, 해당 칸이 이동 가능한 통로로 남는지 확인한다.
6. 각 필수 품목을 담았을 때 장바구니 순서와 목록의 담음 상태, 점수가 맞게 갱신되는지 확인한다.
7. 일반 함정 물건과 TNT를 담았을 때 각 감점 및 TNT 즉시 종료가 맞는지 확인한다.
8. 필수 품목만 담고 계산하기를 마지막에 실행해 결과 화면으로 이동하는지 확인한다.
9. 계산하기를 빼거나 중간에 배치해 결과 화면으로 넘어가지 않고 안내가 나오는지 확인한다.
10. 플레이 화면에서 상단 흰색 바와 긴 규칙 패널이 없고, 장보기 목록·지도·장바구니·블록·컨트롤이 스크롤 없이 보이는지 확인한다.
11. 결과 화면과 레벨 재시작/변경 동작이 선택 레벨의 장보기 데이터와 일치하는지 확인한다.

## 10. 구현 순서 제안

1. 게임 데이터를 2개 장보기 레벨과 새 아이템 목록으로 교체하고 지도 크기를 맞춘다.
2. 계산대 종료를 제거하고 `계산하기` 블록 및 마지막 블록 완료 검증을 추가한다.
3. 케이크·레시피 UI를 장보기 목록·장바구니·장보기 결과로 교체하고 점수를 연결한다.
4. 규칙 패널과 상단 바를 제거하고, 기존 스타일을 보존하며 화면 높이를 조정한다.
5. 완료 기준과 확인 시나리오로 레벨, 블록 종료, 점수, 화면 배치를 검토한다.
